> README 规则来源：造物主 P-C 拍板（2026-08-30 23:04）——「README 要展示纯手工流：告诉世人如何手工编辑 HTML，而不是告诉他们怎么修改 xlsx 和运行 py」。

## 一、README 是什么（定位）

- **公开层「唯一权威决策手册」**（仓库根，首读锚点：MEMORY 步骤 → README 公开层 → 契约解释层）
- 面向**「想自建同类导航站的人」**的**纯手工流教程**：教人手写 HTML 搭出同样效果的站
- **不教内部工作流**：xlsx 数据源、py 构建脚本、.workbuddy 治理层一律不出现

## 二、编写规则（7 条，改 README 必守）

1. **纯手工流**：开头明示「不需要任何构建工具或数据源文件，所有内容直接手写进 HTML」；全文教手写 HTML（head 必填/body 结构/卡片/页脚/字段），**禁止出现 xlsx、.py、merge、build 等内部自动化**
2. **零内部引用（公开暴露铁律）**：README 在 .workbuddy/ 外、仓库公开 → 不提 `.workbuddy/`、契约、消融台账、真实统计 ID、GitHub 用户路径
3. **目录树 = 手工视角**：只列手写文件（index/topics/pages/404/css/js/images/json/CNAME/robots/sitemap/ads/favicon）；**不列 assets/xlsx、assets/.build**
4. **章节结构**（固定 11 章）：开头（站名+slogan+新定位+纯手工流声明+第三方声明）/ 一设计语言 / 二站点结构 / 三页面骨架 / 四手写入门 / 五字段手工录入 / 六视觉规范 / 七交互说明 / 八SEO / 九统计广告（HTML 视角）/ 十部署（含上线检查清单）/ 十一FAQ
5. **内容与现状一致**：定位=「综合全品类导航/陈列馆」（非纯政协）；功能清单以当前站点为准（滚动按钮/声明条/外链规则）；**已拍板删除的功能不得出现**（统计授权条、随机漫步——后者 2026-09-28 删除）；部署章节发布源必须写 `docs/`（2026-09-14 变更，README 原写 `/ (root)` 已于 2026-11-25 更正）
6. **改规则改配置不改散落代码**：外链策略规则表放 README §七，实现集中（build link_attr）
7. **漂移即回改**：发现 README 与现状不符 → 回改 README（或现状）→ 记当日日志（前期漂移清单 M-5/M-7 教训）

## 四、决策库机制（DEC，治理级）

- **单一权威 = 宪法 + DEC 库**：治理级决策（DEC-001~011…）入宪法 §三 DEC 库；产品级决策（D-xx/N-xx）由 01 产品定义文末决策记录承载（DEC-007：每条含原因）。
- **编号规则**：DEC-012 起由执行负责人登记、造物主拍板生效；不得两处说法不同（三铁律第 1 条）。
- **记录要素**（DEC-007）：编号 / 决策内容 / 选择的原因 / 拍板日期 / 状态（生效/废止）。
- **废止留痕**：功能删除（如随机漫步 2026-09-28）记入决策记录与当日日志，契约正文只留废止指针，不留玩法细节。

## 五、变更管理（可执行）

1. **先记日志后动手**：任何实质改动（建站/改 bug/写报告/改架构/选方案）先在当日日志记一笔（三铁律第 2 条，无记录=无效动作）。
2. **备份可回档**：结构性改动（重排/改名/删除）先备份到 backups 目录并写 MANIFEST（含回档说明）。
3. **逐条拍板**：造物主逐条确认，不批量、不越权（三铁律第 3 条）；agent 只执行已拍板项。
4. **引用同步**：改名/改章节后全仓 grep 引用并同步，核验零死链（2026-11-26 两次重构的教训）。
5. **回归闸门**：改 main.js → qa-scroll-check.js；改 #consent-bar → qa-consent-check.js；改契约 → 核验指针目标存在。
6. **坐标保护**：公开层（README/docs）零仓库坐标真值；改公开文档后 grep 扫描。
7. **git 全停**：agent 不执行任何 git 操作，仅提醒未提交文件，由造物主收口。
