## 一、架构总览（陈列馆形态，非传统导航）

- **本质约束**：本站是主题卡片陈列馆 / 百科索引，不是导航站。信息架构服务于"按主题陈列词条"，卡片可无链接（空行占位=信息）。
- **两级结构**：首页（唯一，政协+民主党派专题）→ 子频道专题（gov / search / snh48 / bankcode…，未来持续扩展）。综合全品类 = 不断扩展子频道。
- **语义隔离**：`topics/` = 专题频道页；`pages/` = 说明/合规/功能页；`articles/` = 站长随笔（非索引内容）；`index.html` = 首页专题。四者边界不可混用。
- **流量入口**：域名 + 名称吃政协自然流量，但站是综合陈列馆；政协专题只是首页的一个频道（D-01~03）。合规切割见 08 合规规范。

**URL 规则**：
1. 专题统一挂在 `topics/` 下（废弃旧 `directory/`），目录名见 §五。
2. 每页 `<link rel="canonical">` 指向完整 URL；JSON-LD 按层级映射（首页 WebSite、hub CollectionPage、专题/子页 WebPage + BreadcrumbList）——实现见 05 构建规范 §二。
3. 导航内链 = 完整 URL、静态资源 = 相对路径（B 方案，见 05 §三·补）；本契约只定层级，不定 URL 生成实现。
4. 新增页面必须同步 sitemap.xml（SEO 校验由 06 校验与上线把关）。

## 四、导航逻辑

1. **首页**：hero → 分类行（点 Logo=全部）→ sticky 区（站内搜索/结果计数/筛选标签）→ 卡片 Grid → 页脚 + 滚动按钮 + 声明条。
2. **专题 hub**：channel-grid 频道卡（首字图标 + 标题 + 描述 + 进入频道），**无筛选 JS、无滚动按钮**。
3. **专题页**：与首页同骨架，频道标题/导语 + 该频道卡片。
4. **页脚导航**：全站统一完整 URL 链接；typed 手写页与生成页一致。
5. **筛选**：分类 + 关键词 + 本地收藏三维 AND 叠加，状态可 URL 分享（`#cat=`）——交互实现见 04 设计规范。

## 六、新专题变更流程（可执行）

1. 造物主提出专题立项 → 逐条拍板：中文名 / 目录名 / 分类体系 / 是否政务类（合规 Attribute 词）。
2. 拍板后：建 `pages.unified.xlsx` 行（`dir_path`/`title`/`description`/`keywords`/拼装字段）——字段见 03 数据模型 §二。
3. 造物主在 `cards-pages/` 建对应 xlsx → merge → build 生成页面。
4. 更新本契约 §二页面层级表 + §三分类体系 + §五命名表（**同步架构文档，防漂移**）。
5. 更新 sitemap.xml → 跑 06 校验与上线的 L1/L4 → 造物主拍板上线。
6. 记当日日志（含决策原因，DEC-007）。
