### 2.2 v3 新增功能详解

#### 多标签交集筛选（方案 01）

- **四层筛选逻辑**：分类筛选 AND 收藏筛选 AND 搜索标签 AND 实时搜索
- **标签操作**：点击搜索按钮/回车 → 生成标签 → 输入框清空
- **标签管理**：每个标签带 × 删除按钮，≥2 个标签时显示「清除全部」
- **标签去重**：不区分大小写，已存在不重复添加
- **动效**：生成（淡入+下滑+展开）/ 删除（淡出+收缩）
- **移动端**：标签栏横向滚动 + 右侧渐变遮罩

#### 卡片底部扩展（方案 02）

卡片从 3 层扩展为 5 层：
```
┌─────────────────────────────────┐
│  🟥 图标    网站名称        ⭐  │  第1层：图标 + 名称 + 收藏
│         网站描述                 │  第2层：描述
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │  主分隔线（淡金色）
│  🏷 设计  🏷 在线  🏷 协作       │  第3层：标签行（点击=筛选）
│  🔗 官网  💬 知乎  🐙 GitHub    │  第4层：链接行（点击=跳转）
└─────────────────────────────────┘
```

**标签行：**

- 样式：象牙金底 + 深棕金文字 + 极细金描边 + 4px 圆角 + 11px 字号

**链接行：**
- 每卡 3 个链接（官网 + 百度搜索 + 特色链接）
- 6 种链接类型：官网、百度搜索、知乎、GitHub、文档、B站

## 三、技术架构

### 3.1 混合方案架构

```
┌─────────────────────────────────────────┐
│           data/sites.json               │  ← 唯一数据源
│     （46 网址 + 标签 + 链接）            │

         ▼               ▼

```

```
        AND 满足输入框实时搜索（如果有内容）
```

## 四、快速部署（3 步上线）

### 4.1 准备工作

1. 一个 GitHub 账号
2. 源码包（nav-v3.zip）

### 4.2 部署步骤

**第一步：创建 GitHub 仓库**
- 登录 GitHub，新建一个仓库（比如叫 `nav-site`）
- 选择 Public（公开仓库才能免费使用 GitHub Pages）

**第二步：上传源码**
- 解压源码包，将所有文件上传到 GitHub 仓库（保持目录结构）
- 确保根目录下有 `.github/workflows/deploy.yml` 文件

**第三步：启用 GitHub Pages**
- 进入仓库 Settings → Pages
- Source 选择「GitHub Actions」
- 触发一次部署（可以随便改个文件提交，或者手动触发 workflow）

**部署完成后，你的网站地址是：**
`https://你的用户名.github.io/仓库名/`

### 4.3 部署前必读 3 件事

⚠️ **1. 修改域名**
- 打开 `public/sitemap.xml`，把 `https://example.com/` 改成你的网站地址
- 打开 `public/robots.txt`，把最后一行的 Sitemap URL 改成你的地址
- 如果用自定义域名，修改 `public/CNAME` 文件

⚠️ **2. 确认统计和广告配置**
- 打开 `public/data/sites.json`，找到 `analytics` 字段
- 百度统计 ID 和 AdSense client 已预置示例值，确认是否需要替换为你自己的

⚠️ **3. 重新构建静态 HTML**
- 如果你修改了 `sites.json` 中的网址内容，需要重新运行构建脚本
- 本地构建：`python tools/build_site.py`
- 或者 push 到 GitHub 后，GitHub Actions 会自动构建

## 五、自定义指南

### 5.1 增删网址

所有网址数据都在 `public/data/sites.json` 里，这是唯一数据源。

**添加一个网址：**
```json
{
  "name": "网站名称",
  "url": "https://example.com",
  "icon": "🌐",
  "desc": "网站描述",
  "tags": ["标签1", "标签2", "标签3"],
  "links": [
    { "type": "官网", "icon": "🔗", "url": "https://example.com" },
    { "type": "知乎", "icon": "💬", "url": "https://www.zhihu.com/topic/xxx" }
  ]
}
```

把这段加到对应分类的 `sites` 数组里就行。

> **修改后记得重新构建：** 运行 `python tools/build_site.py` 重新生成静态 HTML，或者 push 到 GitHub 后自动构建。

### 5.2 标签库说明

**统一标签库（28 个）：**
- 工具属性：在线、免费、开源、协作、轻量、专业、高效、稳定
- 内容类型：教程、资讯、社区、论坛、题库、文档、工具、设计、开发
- 语言地区：中文、英文、国内、国外、需翻墙
- 使用形式：APP、小程序、网页、插件

每个网站配 3 个标签，从上面的标签库中选择，保持标签体系统一。

### 5.3 链接类型说明

**6 种链接类型：**

| 类型 | 图标 | 说明 | 是否可自动生成 |
|------|------|------|--------------|
| 官网 | 🔗 | 网站主地址 | ✅ 自动使用主 url |
| 百度搜索 | 🔍 | 在百度搜索该网站名称 | ✅ 自动拼接 |
| 知乎 | 💬 | 知乎相关话题/专栏/账号 | ❌ 手动配置 |
| GitHub | 🐙 | 代码仓库 / 官方账号 | ❌ 手动配置 |
| 文档 | 📖 | 官方文档 / 帮助中心 | ❌ 手动配置 |
| B站 | 📺 | 官方账号 / 教程合集 | ❌ 手动配置 |

**建议：** 每个网站至少有「官网」和「百度搜索」（自动生成），再加 1 个特色链接。

### 5.4 修改网站名称和描述

打开 `public/data/sites.json`，修改 `site` 字段：

```json
"site": {
  "name": "你的网站名称",
  "subtitle": "副标题",
  "description": "网站描述",
  "keywords": "关键词1,关键词2,关键词3",
  "author": "作者名"
}
```

### 5.5 修改配色

打开 `public/css/style.css`，修改顶部的 CSS 变量：

```css
:root {
  /* 主色 — 想改主色调就改这几个 */
  --color-vermilion-500: #E8453C;  /* 品牌主色 */
  --color-vermilion-700: #A82028;  /* 主色深色 */
  --color-gold-500: #FFC107;       /* 金色 */
  --color-gold-700: #C9A24A;       /* 金色深色 */
  /* ... 其他变量 */
}
```

### 5.6 配置百度统计

1. 登录百度统计（https://tongji.baidu.com/）
2. 创建网站，获取统计 ID（一串 32 位的字符）
3. 打开 `public/data/sites.json`，找到 `analytics.baidu.id`，替换为你的 ID

### 5.7 配置 Google AdSense

1. 登录 Google AdSense（https://www.google.com/adsense/）
2. 获取你的 client ID（格式如 `ca-pub-xxxxxxxxxxxxx`）
3. 打开 `public/data/sites.json`，找到 `analytics.adsense.client`，替换为你的 ID
4. 同时替换 `slots.top` 和 `slots.bottom` 为你的广告位 ID

### 5.8 配置自定义域名

1. 在你的域名服务商（如阿里云、Cloudflare）添加 DNS 解析：
   - CNAME 记录：`www` → `你的用户名.github.io`
   - 或者 A 记录：`@` → GitHub Pages 的 IP 地址
2. 修改 `public/CNAME` 文件，填入你的域名（如 `www.example.com`）
3. 在 GitHub 仓库 Settings → Pages 中配置自定义域名
4. 等待 DNS 生效（可能需要几小时到 48 小时）

## 六、每日数据推送脚本

### 6.1 功能说明

自动从百度统计 API 获取前一天的数据，生成 HTML 格式的日报邮件，发送到指定邮箱。

### 6.2 配置方法

打开 `tools/daily_report.py`，修改顶部的 `CONFIG` 字典：

```python
CONFIG = {
    "baidu": {
        "access_token": "你的百度统计access_token",
        "site_id": "你的网站ID",
    },
    "smtp": {
        "host": "smtp.qq.com",
        "port": 465,
        "sender": "你的邮箱@qq.com",
        "password": "你的邮箱授权码",
    },
    "email": {
        "to": "收件人邮箱",
        "subject": "网站数据日报",
    }
}
```

> **安全建议：** 敏感信息（access_token、邮箱密码）建议通过环境变量传入，不要硬编码在代码里。支持的环境变量：`BAIDU_ACCESS_TOKEN`、`SMTP_PASSWORD`、`SMTP_SENDER`、`EMAIL_TO`。

### 6.3 运行方式

```bash
# 本地运行
python tools/daily_report.py

# 用环境变量传入密钥（推荐）
BAIDU_ACCESS_TOKEN=xxx SMTP_PASSWORD=xxx python tools/daily_report.py
```

### 6.4 定时自动发送

可以用 GitHub Actions 定时运行，每天早上自动发送日报。在 `.github/workflows/` 下新建一个 workflow：

```yaml
name: Daily Report
on:
  schedule:
    - cron: '0 1 * * *'  # 每天 UTC 1:00（北京时间 9:00）
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Send daily report
        env:
          BAIDU_ACCESS_TOKEN: ${{ secrets.BAIDU_ACCESS_TOKEN }}
          SMTP_PASSWORD: ${{ secrets.SMTP_PASSWORD }}
          SMTP_SENDER: ${{ secrets.SMTP_SENDER }}
          EMAIL_TO: ${{ secrets.EMAIL_TO }}
        run: python tools/daily_report.py
```

然后在 GitHub 仓库 Settings → Secrets 中添加对应的密钥。

## 九、常见问题（FAQ）

**Q: 修改了 sites.json，为什么页面上没变化？**
A: 需要重新运行构建脚本 `python tools/build_site.py`，或者 push 到 GitHub 后等 GitHub Actions 自动构建。

**Q: 本地预览时，网址数据加载不出来？**
A: 因为浏览器的安全策略，直接双击打开 HTML 文件的话，`fetch` 加载 JSON 会失败。用 `python tools/dev_server.py` 启动本地服务器，然后访问 http://localhost:8000

**Q: 百度统计不显示数据？**
A: 百度统计数据有延迟，一般 30 分钟到几小时。确认 ID 正确，且网站有真实访问量。

**Q: AdSense 广告不显示？**
A: AdSense 需要审核通过后才会展示广告，审核周期几天到几周。沙箱环境和本地预览不显示是正常的。

**Q: 怎么备份我的数据？**
A: 最重要的是 `public/data/sites.json` 这个文件，定期备份一下就行。其他都是代码和样式，不会频繁变动。

**Q: 想加暗色模式怎么办？**
A: 当前版本未做暗色模式。如果后续需要，可以在 CSS 中添加 `@media (prefers-color-scheme: dark)` 媒体查询，定义深色主题的 CSS 变量。

**Q: 搜索标签的匹配规则是什么？**
A: 点击卡片标签添加的是精确匹配；手动输入搜索是模糊匹配（includes），可能出现部分误匹配。这是已知优化项，后续版本可改进。

**Q: 卡片上的标签和链接能自定义吗？**
A: 可以，直接编辑 `sites.json` 中每个网站的 `tags` 和 `links` 字段就行。标签建议从统一标签库中选择，保持体系一致。
